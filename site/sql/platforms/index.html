FOUNDATIONS · DATABASE PLATFORMS & DATA MODELS

Same fundamentals.
Different engines.

Separate the product, the language, the architecture, and the data model.

Four ideas that are easy to mix up

Database system

The software that stores, processes, and manages data: SQL Server, SQLite, MySQL, or PostgreSQL.

SQL dialect

The language and extensions an engine accepts. Transact-SQL (T-SQL) is used to communicate with Microsoft SQL Server.

Architecture

Where the engine runs: embedded in the application or as a separate database service that clients connect to.

Data model

How information and relationships are represented: relational tables, persistent objects, or relational systems with object-related extensions.

SQL Server is the product. T-SQL is a language. “Transact” does not limit T-SQL to transactions: a normal SELECT sent to SQL Server is T-SQL too. The names are SQLite, MySQL, and PostgreSQL (often shortened to Postgres).

A server is a running service, not necessarily a different physical computer. It can share a computer with an application. SQLite’s embedded design lets this course run an in-memory practice database directly in your browser.

These engines overlap in capabilities. Do not infer that MySQL cannot support complex queries, that SQLite is not a real database, or that PostgreSQL replaces tables with application objects.

One question, two SQL dialects

Retrieve the three highest-paid employees, breaking salary ties by employee ID. Choose a platform to compare syntax.

SQLite

SELECT name, salary
FROM employees
ORDER BY salary DESC, id ASC
LIMIT 3;

LIMIT caps rows. This is the dialect executed by the course runner.

These are comparison examples, not a multi-engine runner. SQL Server uses TOP (or OFFSET/FETCH for paging). The shared ideas—SELECT, filtering, joining, grouping, and ordering—transfer. Date functions, data types, generated keys, permissions, procedures, and error handling require platform-specific practice.

Relational versus object-oriented

Consider an employee who belongs to a department. Choose a model to see how that relationship is represented.

Rows, keys, and joins

An employees row contains department_id = 10. The departments table has a row with id = 10 and name = Engineering. The key value represents the relationship. A declared foreign key can enforce valid references; a JOIN retrieves the related information.

SELECT e.name, d.name AS department
FROM employees e
JOIN departments d ON e.department_id = d.id;

Object-oriented programming and object-oriented databases are different choices. You can write an object-oriented application against a relational database.

ORM means object-relational mapper. It maps application objects to relational tables. An Employee class saved through an ORM to SQL Server does not turn SQL Server into an object-oriented database.

PostgreSQL’s object-relational label means it retains relational tables and SQL while providing extensible types and functions. It does not mean arbitrary application objects are automatically stored unchanged. JSON support alone also does not determine whether a database is object-oriented.

What this means for interviews

Be able to distinguish the engine from its dialect and explain a foreign key and a JOIN using a concrete example. State which database you actually practiced on.

“I practiced relational queries and database-change scripts in SQLite. I understand that the concepts transfer, while production troubleshooting and platform-specific scripting require practice in the team’s database environment.”

For a support role, also practice explaining how you would reproduce a data discrepancy, inspect relevant records, verify join cardinality and filters, document evidence, and escalate with a clear summary. Completing this lesson does not establish independent production-support competency.
