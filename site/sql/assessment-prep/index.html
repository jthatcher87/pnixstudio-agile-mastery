Design a class-president election system

Support several classes and repeat elections. Each election has its own approved eligibility roster. Candidates must be eligible in that election. An eligible voter may cast one ballot per election for a candidate in the same election. Candidate IDs may repeat between elections. Self-voting is allowed in this lab. Preserve referenced roster records when someone attempts deletion.

Use six tables: classes, voters, elections, eligibility, candidates, and votes. Election eligibility is an authoritative snapshot provisioned from verified enrollment outside this lab. In this design, a ballot records the voter’s identity; discuss the implications for a secret-ballot requirement before adopting it.

Lab table contract and acceptance rules
  • Use the exact table and column names so the checker can load its test fixture. Extra optional columns are allowed.
  • Declare a primary key on every table and the listed foreign-key relationships, including composite relationships.
  • Require class and voter names and election titles; reject NULL and space-only labels.
  • Require all ballot fields. Enforce uniqueness per election, not once for the voter’s lifetime.
  • Reject invalid operations with constraint errors; valid votes must still succeed.
Use CREATE statements only. The runner starts empty, enables foreign keys, supplies fixture data and discards the database after checking. SQLite’s affinity rules do not prove SQL Server’s type behavior.
One defensible design
The composite ballot key enforces one vote per voter per election. Referencing eligibility and candidates through election-scoped keys prevents cross-election references. Eligibility provisioning, authentication, deadlines, auditability and secret-ballot design require further requirements and controls.

    Logical processing order
    Choose the clauses in their simplified logical order for these SQLite SELECT queries. This is a reasoning model for binding and results; the optimizer’s actual physical execution plan can use a different order. In T-SQL, FROM / ON / JOIN also precede WHERE, grouping, HAVING and SELECT; TOP is logically applied after ordering.
      Moving a right-table filter from ON to WHERE can remove the NULL-extended rows of a LEFT JOIN. Use HAVING for aggregate groups. For portable SQL, use source expressions or a CTE when a SELECT alias is not yet available; SQLite accepts some alias shortcuts that SQL Server does not.
      Clean and convert deliberately
      NULL, an empty string and zero mean different things. Normalize space-only strings with NULLIF(TRIM(value), ''). Validate the agreed format before numeric conversion. SQLite can turn invalid text into zero or accept a numeric prefix; a successful CAST alone is not validation.
      -- SQLite: demonstrate the conversion pitfall
SELECT CAST('12x' AS INTEGER), CAST('bad' AS INTEGER);
-- This produces 12 and 0, not validation errors.
      The conversion task accepts only 1–6 ASCII digits after trimming spaces and optionally removing one leading lowercase votes: prefix. It rejects signs, decimal points, arbitrary prefixes, malformed suffixes and overlong values. Zero remains a valid number. This is an explicit practice contract, not a universal cleaning policy.
      -- SQL Server / T-SQL comparison only
SELECT TRY_CONVERT(int,
       NULLIF(LTRIM(RTRIM(raw_points)), '')) AS parsed_points
FROM raw_vote_import;
      TRY_CONVERT returns NULL for many failed conversions, but explicitly disallowed conversions can still error. It does not remove the votes: prefix or enforce this lab’s stricter 1–6 digit format. Apply the format rules separately. T-SQL examples are not executed by this SQLite runner.

      Rehearse the two-part screen
      Use a fresh problem attempt: first describe your model aloud, then write and explain queries without opening solutions. The suggested practice blocks below are your own rehearsal plan, not the employer’s confirmed timing. Record honest notes; a peer should challenge your assumptions.
      20–30 minutes
      Clarify assumptions, sketch entities and write the election DDL. Demonstrate at least one valid and three invalid operations.
      25–35 minutes
      Write a zero-vote tally, explain an outer-join filter, calculate turnout, discuss aggregates and clean invalid numeric text.
